# 错误检查接口与共享匹配模板

2026-11-18，schema 7。替代 schema 6 的接口透传白名单；不修改数据库表结构。模板定义及渠道关联随完整配置版本保存，约 5 秒热更新。

## 行为

请求先按 `/r/<渠道标识>` 找渠道，然后按渠道关联模板的顺序，选择第一个匹配当前请求方法与路径的模板。匹配范围不包括渠道前缀和查询参数。模板有多条匹配规则时满足任意一条即可；命中排除规则时，该模板不匹配，继续尝试后续模板。

- 未命中：使用渠道默认上游地址，保留原始请求方法、正文、查询串和认证头，包括自定义头、query 认证或没有认证的请求。成功和错误状态、正文与端到端响应头均透传，不执行错误规则，不写拦截日志。上游负责验证凭证。不能再根据启用的协议判断辅助接口是否允许访问。
- 命中：使用模板指定协议的上游覆盖和认证设置，继续按该协议验证入站认证、按需要转换出站认证头。错误响应使用现有规则与安全兜底；模板选择检查范围，原有错误规则决定错误分组、文案和状态。不是一命中接口模板就拒绝请求。
- HTTP 状态检查：模板的 `http_statuses` 选择哪些上游状态交给既有 HTTP 错误处理。新模板默认 `400-599`；不在选择范围内的响应透传，但 HTTP 200 还可以独立启用下面的正文检查。这里选择的是上游状态，不是最终返回给调用方的状态；后者由现有错误规则和安全兜底决定。
- `json_sse`：允许对 HTTP 200 JSON/SSE 做正文检查，仍受全局 `inspect_embedded_errors` 开关控制。开启后保留既有解析和大小限制；关闭后，未被 HTTP 状态选择命中的 200 直接透传。
- `http_errors`：不检查返回内容，仅按模板选择的 HTTP 状态处理，适用于图片、音频、大 JSON 等格式。全局正文检查开关不会为该模式启用正文检查。

状态码可以选择常见错误 `400-599`、服务端错误 `500-599`、请求限流 `429`、重定向及错误 `300-599`、不按 HTTP 状态码检查，或自定义输入。例如 `301,400-500,503` 包含 301、400 至 500（包含两端）、503，不包含 501、502。支持英文/中文逗号、空格及多个单码与区间混合；仅接受最终响应状态 200–599，不接受临时响应 1xx。最多 32 项、512 字节；倒序范围、越界值和空项目会拒绝保存/发布。重复、重叠范围不影响结果。

显式空字符串表示不按 HTTP 状态检查，不会关闭单独启用的 HTTP 200 正文检查；显式选中 200 则会将 200 响应也送入 HTTP 错误规则，即使全局正文检查关闭。范围在配置加载时编译，请求只匹配内存范围，无额外数据库访问。

未命中模板不表示无传输约束：渠道必须存在且节点就绪；只转发配置中指定的上游，路径穿越、编码路径、重复斜线仍拒绝。支持 GET/HEAD/POST/PUT/PATCH/DELETE/OPTIONS，不支持 CONNECT、TRACE、WebSocket/Upgrade。逐跳头、Cookie、Origin、Referer 和转发链不传给上游。请求正文最大 16 MiB、并发、超时、取消及 32 KiB 流式复制限制保留；不追随上游重定向、不自动重试或续写。默认透传不承担协议转换、解析模型列表、计费或上游 OAuth 刷新。

未检查接口统一使用渠道默认地址；不会猜测应该使用哪个协议覆盖地址。需要特殊上游地址的辅助接口不应误以为关联错误检查模板是单纯的路由设置。

## 模板与页面

“错误检查接口”页面管理模板：新增、从内置模板创建、编辑、复制、删除和路径匹配测试。匹配测试只运行内存匹配器，不请求上游。模板包含标识、名称、检查协议、返回内容检查、HTTP 状态码、匹配规则和可选排除规则。

内置预设：OpenAI Chat、OpenAI Responses、Anthropic Messages、Gemini 内容生成、OpenAI 图片、OpenAI 音频、Embeddings、Rerank、Anthropic Token 计数。前四个预设使用 JSON/SSE 模式，其余仅检查 HTTP 错误。预设是配置副本，已发布模板不会随程序内置列表变化。预设只定义接口匹配，不表示已经验收所有供应商或请求大小。

渠道编辑中多选关联模板并调整先后顺序。勾选模板时，页面自动启用对应协议；已有协议的特殊上游地址、认证设置不会覆盖。取消关联仍保留协议配置，避免丢失自定义设置；对应协议仍被模板使用时不能手动关闭。不关联模板时整个渠道默认透传。修改共享模板会影响所有关联渠道的新请求；页面显示关联渠道。修改模板协议并保存时，所有关联渠道在草稿中自动补齐该协议，顶部待发布列表同时列出渠道修改；已有覆盖保留，发布前不影响运行。仍被引用的模板不能删除，需先解除关联。保存仅写浏览器草稿，顶部待发布数量包含模板和渠道关联的修改；发布、历史比较和恢复使用完整快照。

支持精确路径、原字符串前缀和正则。前缀 `/v1/chat` 也会匹配 `/v1/chat-extra`，需要目录边界时填写尾部 `/`。正则使用 Go RE2 语法并包裹完整路径锚点，不支持回溯、反向引用或前后查找。方法大小写精确匹配。每模板最多 32 条匹配规则、64 条排除规则；每渠道最多关联 64 个模板；每份配置最多 1024 个模板且总配置上限仍为 2 MiB。正则在快照加载时编译，请求不会访问数据库或重复编译。

## 升级与旧配置

所有节点先升级，再发布 schema 7。旧节点无法读取 schema 7。状态码选择作为 schema 7 模板的可选字段保存，不增加数据库表；发布带 `http_statuses` 的配置前，也必须将所有节点更新到支持该字段的程序，避免旧程序忽略选择范围。

初期 schema 7 若缺少 `http_statuses`，兼容原有行为：`json_sse` 对非 200 最终响应检查（201–599），并保留原有 200 响应解析；`http_errors` 检查 400–599。新版编辑器显示这个实际范围，新建模板及内置预设则默认 400–599。编辑并保存后使用显式状态选择与正文检查开关。

新版程序读取 schema 3–6 时，在数据面保留旧路由逻辑，包括原路径准入、凭证检查和 schema 6 白名单；只升级程序不会自动开放接口。运维页面显示转换预览和一项待发布的配置升级，发布后才切换默认透传。schema 2 继续需要显式转换，旧凭证不会恢复。

转换预览按各渠道原有启用协议关联前四种预设，并明确保留其原非 200 检查范围 201–599；原白名单覆盖已检查的生成接口时，生成带精确排除规则的渠道专用模板，避免重新启用这些接口的检查。原白名单其他条目移除，未检查请求在发布后改用渠道默认地址和原始认证。原白名单曾选择特殊上游覆盖或认证转换时，运维必须核对这项行为变化，页面明确提示。渠道、协议覆盖、并发、错误规则保留，schema 3/4 的原有默认转换继续适用。

旧历史快照不改写，历史查看/恢复提供同样的转换预览；恢复也是发布新版本。已开始的请求保留原内存快照和连接。发布新格式后不能直接降级旧镜像。

## 验证范围

回归检查覆盖模板校验与加密快照、旧版本运行和转换、默认透传多种认证与错误原文、协议覆盖、共享模板更新、匹配顺序、HTTP-only 二进制成功响应、已有 JSON/SSE 错误处理、并发和旧流生命周期。状态码测试覆盖单码/范围边界、无效输入、未选择状态及重定向原样透传、显式 200、空选择和独立正文检查。独立 PostgreSQL 双节点浏览器检查覆盖状态码预设/自定义、无效范围、保存回显、发布与两节点实际响应、模板编辑、无效正则、试匹配、引用删除限制、关联排序、待发布计数、发布同步及检查/透传变化。真实供应商与生产容量仍需独立验收。

## 控制台交互简化（2026-11-19）

- 渠道编辑默认展示名称、标识、上游地址和模板勾选。匹配顺序单独折叠；HTTP 开关、协议启用项、特殊地址和认证头放入高级设置，并显示已允许 HTTP/已有覆盖的摘要。新渠道不预先启用任何检查协议，勾选模板后自动添加；取消整个编辑不会修改草稿。
- 模板编辑默认展示名称、HTTP 状态预设/自定义和返回内容检查。标识、协议、路径匹配、排除及试匹配放入高级设置；新增自定义模板自动展开，便于填写必需路径。从内置模板创建或编辑已有模板时默认收起。
- 错误规则按“匹配什么错误”和“返回什么结果”组织。规则 ID、协议与来源限制折叠到高级匹配设置，已有筛选限制会在摘要中标明；使用自然语言说明条件组关系。错误规则状态过滤不会扩大接口模板指定的检查范围。
- 拦截日志列表展示渠道、命中规则、上游与实际返回状态以及安全响应/安全错误事件等处理结果。原始内容继续在详情中查看，不增加日志采集或写入。
- 旧配置升级提示先说明“核对渠道接口后发布”，具体路由和认证影响可展开查看。保存草稿、待发布计数、统一发布和离页提醒保持原有流程。本次交互调整不涉及表结构或数据面规则变化。

模板管理列表使用紧凑表格展示模板名称、检查协议、上游状态范围、HTTP 200 正文检查、关联渠道、接口规则和操作。支持名称/标识/路径搜索、协议与关联情况筛选；规则和关联渠道按需展开。手机端按字段分组显示，避免横向滚动。201–599 显示包含成功/重定向的提示，不自动修改旧模板或发布配置。正文检查列显示当前草稿中的全局开关状态。
