# 首次开发交付与验收记录

> 本文保留首次 schema v2 实现的验收历史，其中上游 Key 管理和内部令牌已在后续修订中移除。当前行为、升级方式和新验收结果见 [凭证转发说明](credentials-passthrough.md)。

日期：2026-11-17（Asia/Shanghai）。开发分支：`codex/gateway-console-config-versions`。设计决策于 2026-11-16 确认，见 [设计 v2](design-v2.md)。本次只进行本地开发、模拟验收和本地镜像构建；未推送代码、发布远程镜像、部署生产或调用付费模型。

## 已实现

- 中文运维页面：管理员登录、渠道新增/修改/删除、四协议选择、地址/Key/认证覆盖、内部令牌生成和复制。
- 完整配置版本：独立加密快照、数据库事务发布、过期编辑冲突检测、不可变历史、脱敏查看、恢复为新版本。
- 多节点：5 秒检查、完整校验和热切换、实际生效版本和摘要、节点错误/离线状态、在途请求数。正常退出释放身份登记，拒绝的重复节点不能释放原节点登记。
- 数据面：Chat、Responses、Messages、Gemini；按协议内部认证和出站凭证；非成功 HTTP 错误隔离；正常 JSON/gzip/SSE、完整用量保真；取消、超时、并发和大小限制。
- 管理与数据监听分离；秘密文件独立，加密快照不在 API 回显明文；管理页面无第三方资源、无 localStorage 令牌、拒绝跨站写入。
- 固定 Go 1.26.10 和镜像摘要，CGO=0 发布二进制，非 root / scratch + CA。未配置数据库时保持旧 bootstrap 模式。

## 50 渠道配置实测

在只读、非 root、上限 128 MiB 的候选镜像容器中发布 50 个模拟渠道，每个启用四种协议：

| 指标 | 本次观测 |
| --- | --- |
| 完整配置 JSON 大小 | 14,775 字节，约 14.4 KiB（加密前） |
| 发布到节点报告已生效 | 约 5.04 秒；与 5 秒轮询一致，不是延迟 SLA |
| 四协议模拟请求 | 4 次，本地 HTTP 模拟上游；无真实模型请求 |
| 容器内存采样 | `docker stats` 约 5.17 MiB / 128 MiB；属于低负载单次采样，不是峰值 RSS 或容量证明 |
| 正常用量/头部 | 保留缓存用量字段；移除虚构余额头 |
| 认证/秘密 | 错误内部令牌拒绝；版本 API 不返回上游 Key 和内部令牌 |

原始记录在本地 `build/configured-image-smoke.json`。这些数据只证明几十个渠道配置的存储和同步可以正常工作；未进行代表性长流、高并发、故障网络容量测试。

## 已知限制与上线前验收

1. HTTP 200 正文、SSE 内嵌错误及其中的敏感信息仍透传；不能宣称全面防泄露。
2. Sub2API、kiro2cc 专用兼容规则未伪造实现；当前仅 `standard_v1`。需要实际项目版本和脱敏样本验证后再添加规则。
3. 未对真实 New API 的协议拼接、渠道自动测试、禁用/重试策略、计费/预扣/退款进行验收。模型列表等首版外接口不开放。
4. 没有自动重试、续写、供应商切换和负载均衡控制面；多节点配置是最终一致，运营先确认同步再启用 New API 渠道。
5. 无磁盘最近有效快照缓存：已有进程数据库中断时继续服务；重启或新节点无法读到有效配置时保持未就绪。
6. 数据库、管理端 TLS、最小权限账号和备份需部署时配置。主密钥自动轮换迁移尚未实现；丢失主密钥不能解密历史。
7. 停用/撤销配置不会强制中断旧流；失联节点可能继续旧配置。紧急撤销需要单独隔离失联节点或撤销上游真实凭证。
8. 本地镜像标为开发版本，源码处于工作区变更状态，非正式发布产物。镜像 publication digest 与生产部署记录需正式发布时另行生成。
