# 发布与登录交互

2026-11-18。本次只调整内嵌运维页面及前端验收，不修改配置 schema 5、数据库表或后端接口，无需数据库迁移。镜像中的静态资源需要随新镜像更新。

## 草稿与批量发布

渠道和错误规则继续“保存到草稿”；并发设置和正文检查开关仍先修改当前页面草稿。顶部常驻“待发布 N 项”角标，滚动或切换标签页也能找到。底部固定发布栏移除，“重新加载最新配置”移动到编辑基线附近，有未发布草稿时先确认放弃。

角标按已保存到草稿的最终配置差异统计：同一渠道的多个字段或重复修改合计一项；每条规则合计一项；并发设置整体一项；正文检查开关一项。改回原值、新增后又删除会移除相应项目。规则顺序影响匹配，因此共有规则相对顺序改变时，位置发生变化的规则也计入；仅增删规则不把其他规则的序号顺移算作修改。编辑窗口尚未保存的字段不计入角标，但刷新/关闭前仍参与未保存提示。

渠道/规则标签显示各自的待发布数量，与总数量区分。规则行标注新增/修改待发布；已删除项目在发布清单中显示。没有变更时显示灰色“无待发布修改”，按钮禁用，不创建内容相同的新版本。

点击角标弹出变更清单、编辑基线及最新已知版本，输入选填说明后发布全部修改。关闭弹窗保留草稿和说明。存在非法并发输入时，返回并发设置定位修正。名称和清单使用文本节点显示，避免将配置内容当作 HTML。

发布仍向 `/api/publish` 提交完整 config、base_version 和 note。提交期间禁止重复提交和关闭发布弹窗；失败保留清单、草稿和说明并显示原因。版本冲突继续由已有后端拒绝，不自动覆盖别人的修改。请求超时结果不明时提示核对版本历史，不自动重试。

发布得到明确成功响应后立即记录返回的版本并清除该批差异，然后读取节点状态；后续状态查询失败不会把已成功的发布误当成失败，也不再允许重复发布这批内容。同步信息区分“版本已发布”和“节点已生效”，离线或异常的已登记节点不算已同步。

## 登录与刷新

管理员令牌使用 `sessionStorage` 的 `upstream-gateway.admin-token` 保存，仅限本 origin 的标签页会话。初次登录需成功读取管理配置后才保存；刷新先用保存值调用管理 API，成功后恢复控制台。未发布草稿不进入任何浏览器存储，刷新后加载最新已发布配置。

页面初始显示“正在载入控制台”，登录表单在 HTML 中默认隐藏，避免脚本加载或会话验证期间闪现。没有已存令牌、令牌失效或恢复失败需重试时才显示登录页面。

错误规则编辑器的校验提示默认隐藏；保存失败时显示具体原因，再次提交或重新打开编辑器时清空，避免无错误时出现空白红框。

主动退出会提醒放弃未发布/未保存修改，确认后清除会话令牌及本页草稿。任一管理 API 返回 401 时，清除令牌并回到登录页；同一页面重新认证前保留内存草稿，成功后可继续编辑，仍按原 base_version 防止覆盖冲突。迟到的旧会话请求不能覆盖新会话状态。

网络中断或服务端 5xx 不视作退出。刷新恢复失败时保留令牌，显示“重试恢复登录”；恢复网络后可直接重试。存储被浏览器禁止时，仍允许本页登录，明确提示刷新后需重新登录。

sessionStorage 可被同源 JavaScript 读取，不是 HttpOnly Cookie，也没有服务端会话过期/撤销功能。独立打开的新标签页通常没有令牌，但复制标签页、opener 和浏览器恢复会话可能复制/恢复它；不承诺关闭浏览器后一定清除。主动退出登录是明确清除方式，管理员令牌的后端校验与原有同源保护继续生效。

## 验证范围

使用独立内存模拟 API 的 `scripts/browser-layout-smoke.cjs` 验证角标去重/还原、全量发布弹窗、版本冲突保留、发布后状态失败、移动布局、XSS 文本显示、刷新保留登录而丢弃草稿、401 清除、重新登录恢复本页编辑、退出清除、独立标签页及存储禁用退化。

`python3 scripts/check-error-rules.py` 使用临时 PostgreSQL 与两个临时节点，验证真实发布接口、节点同步和规则/日志回归；不在用户的验证数据库或生产环境运行测试发布。

刷新回归会分别暂停页面脚本加载和认证请求，确认两个阶段登录表单均不可见；规则编辑器回归检查初始无红框、非法输入显示原因、修正后提交清除提示。
