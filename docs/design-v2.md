# 网关配置、运维页面与多协议设计 v2

日期：2026-11-16；2026-11-17 修订为 New API 凭证随请求转发；错误规则与日志扩展为 schema 4，详见 [实施说明](error-rules.md)；动态并发扩展为 schema 5，详见 [并发设置](concurrency.md)。本文记录本次用户确认的实施契约。替代旧设计中的“没有数据库、没有管理页面、不热更新、一条路由仅一种协议”；其余错误隔离、计费保真、无自动重试约束继续有效。完成情况和实测结果另见交付记录，不把设计当作已验证能力。

## 1. 本版目标

- 独立 Go 1.26.10 网关，New API 负责用户、模型选择、余额与结算。
- 必须提供中文运维页面：管理渠道、选择多协议、发布全量版本、查看脱敏历史、回滚、查看每个节点实际生效版本与错误。
- PostgreSQL 集中保存配置；节点直接读取数据库，每 5 秒检查最新发布版本。模型请求仅使用内存。
- 一个渠道入口 `/r/<id>` 支持 OpenAI Chat、Responses、Anthropic Messages、Gemini。模型品牌不是协议判断依据。
- 不自动重试、续写、换模型、切上游；每个入站模型请求最多一次应用层上游尝试。

## 2. 配置对象与完整版本

一份 schema 5 配置包含 channels、error_rules、inspect_embedded_errors 和 traffic_limits。每个渠道具有唯一 id、名称、默认 base_url 和已启用 protocols。每种协议可覆盖 base_url、上游认证头格式和兼容组件。配置中没有上游 Key 或网关内部令牌。入口固定 `/r/<id>`，避免歧义前缀。

V1 保存 A/B，V2 保存 A/B/C，V3 保存 A/修改后的 B/C。每次点击发布保存完整独立快照，已发布版本不可修改。节点加载完整快照，不应用增量补丁。回滚是将历史内容再次发布为更高版本。历史不自动清理。

编辑表单是浏览器内草稿；刷新页面会丢弃未发布编辑。发布带 base_version，数据库事务锁保护版本递增；如果其他人已经发布则返回冲突，禁止覆盖未知修改。发布前严格校验、初始化后才能写入。空配置是合法的停用全部渠道版本。

完整快照继续使用 AES-256-GCM 加密，主密钥由只读文件提供；它保护配置和旧历史，不是上游 API Key。新 schema 明确拒绝 key、key_set、internal_token、token_set 等旧字段，页面/API 不再接收或返回这些字段。

真实上游 Key 由 New API 请求携带，仅存在于该请求的内存生命周期，不写入配置、版本和普通日志。旧 schema v2 历史不可变，原有密文保留；历史查看和恢复先去除凭证字段，转换为 schema 5。schema 2 必须重新发布；schema 3/4 可继续加载，并发采用默认值，schema 3 保持正文检查关闭。详见 [凭证转发与升级说明](credentials-passthrough.md)。

## 3. 节点同步及生命周期

读取最新版本号，无变化仅报告心跳。有变化则读取该不可变记录，校验摘要、解密、校验 schema/协议，构造不可变运行快照，成功后一次性切换指针。失败保留旧版本并报告固定错误类别。每个请求持有它开始时的快照，直到 JSON/SSE 完成；不原地改地址；请求所带 Key 独立保留到该请求完成。

| 操作 | 行为 |
| --- | --- |
| 新增路由 | 生效后新请求可用 |
| 修改地址 | 新请求使用新地址，已有请求继续旧地址 |
| 在 New API 修改 Key | 下一次请求携带新 Key，无须发布网关配置 |
| 删除路由 | 新请求拒绝，已有请求完成 |
| 更新错误 | 不切换，报告错误和当前实际版本 |
| 数据库暂时故障 | 已运行节点使用最后有效内存配置；新节点无有效配置不就绪 |

节点独立报告 node_id、进程实例、目标版本、实际生效版本、摘要、最近检查、错误、在途请求数。心跳超过 20 秒显示离线/未知，不把数据库中旧记录当实时状态。重复 node_id 的活跃进程不得互相覆盖。正常退出只释放自己的进程登记，允许立即重启；异常失联等待 20 秒过期后接管。版本状态针对新请求，旧 SSE 可继续运行。数据库故障期间可能继续使用旧路由配置；紧急撤销需单独隔离节点/撤销真实上游 Key，不承诺离线节点即时撤销。

正常运营：编辑网关 → 发布 → 查看目标节点已应用 → 配置/启用 New API。接受秒级最终一致，不实现全节点同时切换，不引入自动流量切换。

## 4. 协议与上游差异

| 协议 | POST 路径 | 默认请求认证头 |
| --- | --- | --- |
| openai_chat | /v1/chat/completions | Bearer |
| openai_responses | /v1/responses | Bearer |
| anthropic_messages | /v1/messages | x-api-key |
| gemini | /v1beta/models/{model}:generateContent、:streamGenerateContent（同时支持 v1） | x-goog-api-key |

只有启用协议和允许方法/路径才可访问。Gemini 流式允许 alt=sse，Messages 允许 beta=true；其他 query、重复 query、URL 凭证拒绝。渠道默认地址共享，可按协议明确覆盖。入站按协议读取唯一认证头：Chat/Responses 的 Bearer、Messages 的 x-api-key、Gemini 的 x-goog-api-key。缺失、空值、重复、混用认证头和非法格式在本地拒绝；Key 的有效性由上游判断。默认保持认证值；显式认证格式覆盖只改变出站头的承载方式，Key 本身不变。不同请求可以向同一路由提供不同 Key。

公共层负责 HTTP 传输和非 200 隔离；协议层负责路径、认证默认值、安全错误格式；可注册静态编译的兼容组件。当前仅 standard_v1，未知组件发布/加载失败。Sub2API、kiro2cc 按实际版本和协议接入，未有真实样本不得虚构专用修复组件。

正文检查默认关闭，沿用原始转发；开启后按有界 JSON / SSE 协议解析识别明确错误，并匹配版本化规则。不会搜索正常模型文本，不伪造结束或 usage；未知格式仍需脱敏样本验证。具体识别范围和预算见 [错误规则](error-rules.md)。

## 5. 数据面及资源

独立数据监听与管理监听。上游根地址仅来自管理员配置，默认 HTTPS；测试本地 HTTP 需要显式 allow_http。拒绝 userinfo/query/fragment、编码分隔符/路径穿越/重复斜线。有限的请求/响应头白名单，只转发校验后的一个认证头，删除其他认证载体、Cookie、转发链、Location、余额头、trailer，不传播 1xx，不跟随重定向。

只有 200 且 JSON/SSE 类型和 identity/gzip 编码受支持才转发；默认保留 400–599 状态并生成安全协议错误，其他状态/协议升级使用安全 502；命中规则可指定错误状态。SSE 已提交状态无法改变。关闭检查时正常正文保持原字节；开启 gzip 检查后可未压缩转发，正常内容与 usage 保留。

默认全局最大 32 个请求、请求正文最大 16 MiB、头最大 32 KiB、32 KiB 复制缓冲；请求头 10 秒、连接/TLS 10 秒、响应头/上游空闲 180 秒、每次下游写入 30 秒、总请求 1800 秒。取消传播上游。复用 Transport；每节点总并发和每上游请求并发可动态配置，默认 32 / 16，超限立即 503，不排队；HTTP/2 同样按请求计数。配额跨配置版本共享，不能靠热更新翻倍。流出错中断，不追加 JSON 或 DONE。

关闭时先标记不就绪，停止新请求，排空最多 30 秒，超时取消剩余请求。健康只代表进程存活，就绪不代表真实上游/计费已验收。

## 6. 运维页面与访问控制

页面包含渠道表单（多协议和覆盖设置）、发布说明、历史版本脱敏详情与回滚、节点同步表及节点所用版本内容。使用 Go 内嵌静态页面，不增加独立前端运行服务。页面不需要手写 JSON 才能完成日常配置。

数据面不再使用路由内部令牌，也不把上游 Key 当作网关访问授权。调用来源必须由受限内部网络/防火墙控制，跨机器使用 TLS 与来源限制；不要向公网开放数据端口。能够访问数据端口的调用方可选择已配置路由，供应商负责验证请求所带 Key。

管理员令牌从文件加载；浏览器登录后用当前标签页的 sessionStorage 保持会话，刷新时通过管理 API 验证后恢复。退出/401 清除令牌，网络错误保留；草稿仅内存保留。API 使用 Authorization，不使用 localStorage 或 URL。管理 API 全部认证且限制正文大小；不启用 CORS，JSON 写入，拒绝跨站 Origin。管理默认回环访问，远程使用 SSH 转发或受信任 HTTPS 入口。提供安全响应头/CSP，页面不加载第三方资源。启动无数据库配置时保留 bootstrap 健康模式，不开放业务。

数据库连接、加密主密钥、管理员令牌、node_id、监听地址属于启动配置，不随业务快照热更新。运行节点无需管理员令牌即可同步业务；一个带管理员令牌的实例提供运维页。数据库角色可分为发布者（写版本）与节点（读版本/写自身状态），生产部署另行配置最小权限与 TLS。

## 7. 验收

- 配置严格解码、重复字段/渠道/协议、路径/URL、旧凭证字段、未知组件拒绝。
- 全量版本不可变、发布冲突、回滚创建新版本、加密及旧历史凭证剔除、数据库事务一致性。
- 两节点同步；错误配置保留旧版；数据库中断；重复节点身份；SSE 跨更新不断流；删除路由只影响新请求。
- 四协议路径/认证头/格式覆盖、多请求不同 Key 不串用；错误正文/头/trailer 隔离；JSON、gzip、SSE 和 usage 保真；取消/超时/重定向/无重试。
- 运维登录、编辑新增/删除/覆盖、发布、历史、回滚、节点详情、XSS/跨站写入拒绝。
- Go race、vet、digest 固定镜像构建与容器 smoke；模拟上游验收不代表 New API 或真实供应商验收。

部署生产、发布镜像和真实付费请求不属于此次本地开发。真实 New API 扣费、Sub2API/kiro2cc 版本兼容、目标容量需要后续独立记录。
