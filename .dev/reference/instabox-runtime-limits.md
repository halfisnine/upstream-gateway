# Instabox 免费套餐暂停与冷却核查

核查日期：2026-11-16。依据当日实际读取的官方文档，不是账号实测。

## 核查结果

- 免费套餐空闲 30 分钟自动暂停；空闲暂停没有冷却。
- 每次运行初始上限为 120 分钟，服务根据本次活动逐步延长，最多 480 分钟。不是每天只有 8 小时，也不是账号永久升级成每次默认 8 小时；重新开始运行时从 120 分钟起算。
- 达到最长运行时间后暂停会产生冷却。免费套餐连续触顶的默认冷却：第一次 5–20 分钟，第二次 60–75 分钟，第三次及以后 120–135 分钟。具体结束时间以机器 `cooldownUntil` 为准。
- 官方说明连续计数会在无冷却的运行结束后重置，或在上一次冷却结束至少两小时后才开启下一次运行时重置。这不代表正在进行的冷却可被取消；停止、暂停或改设置均不能缩短已经开始的冷却。
- 冷却期间 exec、SSH、文件访问、公网 URL、wake、resume、start 都被拒绝，返回 `409 machine_cooldown`。按 `Retry-After` / `retryAfterSeconds` 等待。
- 自动暂停的机器可以被 exec、SSH、文件访问、有效公网端口请求和 wake 等唤醒，但仍受冷却限制。用户手动暂停/停止的机器不会通过普通访问或 wake 自动唤醒，需显式 resume/start。
- Activity Lease 可以避免空闲暂停，但不计入免费运行时长延长所需的真实使用活动，不能突破每次最长运行时间。定时 wake 不能消除冷却，也不能据此承诺免费机器 24 小时连续在线。
- 暂停通常保留内存和进程；官方同时说明，若无法恢复内存，会保留文件重新启动。不能保证外部 SSH/HTTP/API 连接在暂停恢复后仍有效。
- 没有核实“必定几秒到十几秒恢复”的保证。自动唤醒接口通常最多等待 45 秒，仍未恢复时可能返回可重试错误；SSH 网关连接等待窗口为 15 秒。等待窗口不是实际恢复耗时或服务承诺。

## 对项目的影响

Instabox 可用于按需开发、调试和海外网络辅助，但连续长任务必须考虑中断。
正式构建与镜像发布已使用 GitHub 托管的 Actions，不依赖 Instabox 持续在线。
本次没有连接账号查询当前冷却时间，没有主动暂停机器或运行触顶测试，未设置任何自动唤醒任务。

## 免费套餐与机器保留期限（2026-11-16 补充核查）

官方定价仍列 Free $0（1 台、4 vCPU / 8 GiB、20 GiB 磁盘），所查定价、存储规则
和更新日志未公告取消整个免费套餐。这是当前政策，不是永远免费的保证。

官方定价 FAQ 公布的是早期账号的五台免费机器优惠在 2026-12-01 00:00 UTC
结束：适用于 2026-10-20 前注册且在 2026-10-25 07:45 UTC 前激活的账号。
此后只允许一台免费机器同时运行，其余暂停，不删除。用户此前提供的套餐已经是
一台机器，不能把这条旧优惠到期解释为该用户免费套餐即将取消。

存储文档说明：默认机器和快照保留到用户删除，停止的机器没有强制寿命，不会
因为停止 7 或 14 天就清除。例外包括显式 `deleteAt` 自动删除期限，以及工作区
被禁用或删除：禁用后保留 30 天再删除，删除工作区则立即删除，无恢复窗口。
`archiveAt` 只会停止机器并保留磁盘，与删除不同。

本次未读取用户账号或机器元数据，不能声称已验证其 `deleteAt`、`archiveAt`
为空或工作区无到期设置。代码和发布产物继续保存在 GitHub / Docker Hub；未提交
改动、仅存于 Instabox 的配置或数据需要单独备份，同平台快照不能替代外部备份。
